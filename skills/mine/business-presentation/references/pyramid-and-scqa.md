# 簡報邏輯原則：金字塔原理與 SCQA 故事架構

本文件整理自「用簡報來鍛鍊邏輯與領導」教材的核心方法論。製作簡報建議時，請依據以下原則進行故事線設計與頁面結構檢查。

---

## 一、好簡報的四個標準

1. **聽眾聽/看完會採取行動或接受概念** — 這是簡報存在的唯一目的
2. **聽眾聽/看完可以獲得洞見** — 內容要能對聽眾的工作或目標產生助益
3. **透過摘要就能知道整份內容** — 大幅減少理解時間
4. **每一頁標題清楚表達結論，論證過程邏輯嚴謹**

## 二、一頁企劃（簡報前的思考框架）

在撰寫簡報之前，先回答以下八個問題。前兩個是整份簡報的「設計錨點」，所有後續決策都要回扣到這裡：

**核心錨點：**
1. **主要聽眾（TA）是誰？** — 不只是角色，要理解他們的決策情境、在意的指標、可能的疑慮
2. **期望行動是什麼？** — 「讓 [TA] 在看完後 [採取具體行動 / 接受具體概念]」

**支撐分析：**
3. 聽眾在意什麼、期待的目標？
4. 聽眾的知識背景如何？他知道哪些事情？
5. 聽眾可能的疑慮或抗拒點是什麼？
6. 為了說服他，你需要有哪些資訊？
7. 以他的個性，該用怎麼樣的敘事邏輯來講事情？
8. 簡報結束時，TA 要看到什麼才會願意行動？（Next Steps / 成功案例 / ROI 試算 / 風險緩解方案？）

## 三、SCQA 故事架構

SCQA 是建立執行摘要（Executive Summary）的核心架構，用於組織簡報的整體故事線。

| 元素 | 說明 | 範例 |
|------|------|------|
| **S - 情境 (Situation)** | 描述產生問題的背景與當前情境 | "在過去十年來，我們一直在各大主要市場佔據主導地位" |
| **C - 衝突 (Complication)** | 為什麼會造成眼下的狀況 | "如今由於放鬆管制，我們要面臨更激烈的競爭" |
| **Q - 問題 (Question)** | 如何解決造成問題的成因 | "我們要如何應對這種局面？" |
| **A - 解決方案 (Answer)** | 能解決問題成因的解法 | "啟動新的行銷活動和客戶忠誠計劃" |

### SCQA 順序變體

根據聽眾的熟悉程度，可以調整 SCQA 的排列順序：

| 順序 | 適用場景 | 說明 |
|------|----------|------|
| **S-C-Q-A**（經典） | 受眾對背景不了解，例如營運會議中首次聽取的人 | 最經典的結構，專業感強 |
| **A-S-C-Q**（結論先行） | 受眾對背景和衝突已有了解，迫切想知道解方 | 直接了當，適合事業內會議 |
| **C-Q-S-A**（衝突先行） | 聽眾沒有意識到問題的存在 | 突出問題造成迫切感，適合新提案 |
| **A**（僅結論） | 聽眾非常知情，第二次討論等答案的場景 | 開門見山，花更多時間說明解方 |

## 四、金字塔原理

每一頁簡報都應遵循金字塔原理的結構：

```
          結論（標題）
         /     |     \
      論點1   論點2   論點3
      / \     / \     / | \
   證據  證據 證據 證據 證據 證據 證據
```

### 三大核心要求

1. **結論先行**：在標題就講完這頁面的結論，讓聽眾一眼理解要傳遞的訊息
2. **結論要有行動**：結論不能只是描述現況，要包含明確的行動方向或建議
3. **論證要有邏輯**：理由和證據之間要有清晰的邏輯鏈條（可使用歸納法或演繹法）

### 論證方法

- **歸納法**：從多個證據歸納出共同結論
- **演繹法**：從已知前提推導出新結論

### 頁面標題撰寫原則

- 標題應該是「結論句」，而非「主題詞」
- 差的標題：「Q2 影音數據」
- 好的標題：「Q2 影音觀看數落後進度，需透過兩項行動加速追趕」

## 五、營運週會簡報結構建議

依據教材中的最佳實踐，營運週會類型簡報建議涵蓋：

1. **結果 > 發現 > 下一步**
   - 業務範圍的發展態勢（行業比、環比、同比）
   - 目標進程與時間進度（超越與落後的對應行動）
   - 額外協助（人力、資源、跨事業協助）

2. **OKR 更新結構**
   - OKR 變化與原因
   - 對應進度
   - 上週行動
   - 產生的洞見
   - 未來行動

## 六、TA 導向的說服結構

每份簡報的內容頁可以歸入三種說服角色：

1. **建立需求的頁面**（讓 TA 意識到「這件事很重要」）→ 對應 SCQA 的 S 和 C
2. **提供解方的頁面**（讓 TA 看到「這樣做可以解決」）→ 對應 SCQA 的 A
3. **消除疑慮的頁面**（讓 TA 相信「這樣做是可行的」）→ 針對 TA 的抗拒點

設計時確保這三種頁面都有涵蓋。「消除疑慮」的頁面容易被忽略——如果 TA 有已知的抗拒點（成本太高、缺乏案例、執行風險），簡報中必須有專門針對它的論證。

**從期望行動反推故事線：**
- **終點**：期望行動（簡報的最後一頁把 TA 帶到這裡）
- **起點**：TA 目前的認知和態度（決定 S 和 C 怎麼寫）
- **阻力**：TA 的疑慮（必須在故事線中被化解）
- **路徑**：從起點到終點，TA 需要經歷哪些認知轉變？（每個轉變 = 一個章節）

## 七、檢查清單

製作完簡報後，逐頁檢查：

**TA 與期望行動（最優先）：**
- [ ] 整份簡報是否服務於期望行動？
- [ ] TA 的已知疑慮是否被回應和化解？
- [ ] 結尾頁是否清楚指向期望行動？
- [ ] 只看標題串，是否就能引導 TA 到期望行動？

**邏輯與結構：**
- [ ] 標題是否為結論句（而非主題詞）？
- [ ] 結論是否包含行動方向？
- [ ] 論點是否充分支持結論？
- [ ] 證據是否充分支持每個論點？
- [ ] 整體故事線是否使用了 SCQA 架構？
- [ ] SCQA 的順序是否符合 TA 的認知程度？
- [ ] 聽眾看完後能否獲得洞見？
- [ ] 只看標題是否就能理解整份簡報的主要訊息？
